# 数据库发布顺序

- 需求编号：`SITE-001`
- 版本号：`v3`

## 发布顺序

1. 备份主库，确认应用数据库账号具有建表和建索引权限。
2. 部署后端；主节点启动时通过 GORM `AutoMigrate` 创建 `fde_appointments`。
3. 执行 `db-change_SITE-001_v3.sql` 的只读字段访问检查，并在目标数据库检查复合索引。
4. 部署前端静态资源，开放固定同源预约提交。
5. 从页面提交一条明确标记的验收预约，核对 `pending` 记录后删除该验收数据。
6. 无历史数据回填、无旧逻辑清理；观察 API 400/500、限流和数据库错误日志。

兼容窗口内，旧前端不会调用新 API；新后端增加的公开路由和新表不影响已有业务。

# 数据库回滚

- 需求编号：`SITE-001`
- 版本号：`v3`

## 触发条件

- 新表迁移失败，导致应用无法启动。
- 预约 API 持续返回 500，且确认与本轮表结构或应用逻辑有关。
- FDE 表单造成不可接受的数据质量或安全问题。

## 回滚步骤

1. 下线或回退新前端，停止产生新的预约请求。
2. 回退后端应用；旧版本不会访问 `fde_appointments`。
3. 默认保留新表和已收集预约，避免不可逆删除客户数据；限制表访问并保留备份。
4. 执行 `db-rollback_SITE-001_v3.sql` 的只读数量核查，记录回滚时数据量。
5. 只有在数据已导出、业务负责人和数据库管理员共同批准后，才按目标数据库方言人工执行 `DROP TABLE fde_appointments`；项目不提供自动删表语句。
6. 验证旧首页、通知、控制台和其他 API 正常。

该回滚方案优先应用回滚与数据保留；不存在需要反向回填的旧表。
